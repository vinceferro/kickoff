# §5 THE PLUGIN — locked build spec

Source: planner scope (2026-07-06) + coordinator scrutiny + spike verdict (`brownfield-plugin-cache-spike-2026-07-06.md`). This is the un-steerable brief; build to it exactly. Design of record: `brownfield-devex-design.md` §1.3/§2.1/§2.2/§2.3/§2.4/§7-step-5. Built in **two passes**: Pass 1 = slices 1–4 (forward path); Pass 2 = slices 5–8 (guardrails + reversal + gate). Coordinator verifies between passes.

## Architecture (spike-confirmed)
A local-path marketplace **snapshots a byte-copy of the plugin** into the user-global cache `${CLAUDE_CONFIG_DIR:-~/.claude}/plugins/cache/<mkt>/<plugin>/<version>/` and runs the **interactive** session from that copy — not source. The **headless** path execs source via `--plugin-dir` (cache-free, drift-free). So: plugin lives in the pulled clone at `~/kickoff-core/plugin/` (pull versions + whole-tree-lock pins it); its `version` is baked into each `core-v*` tag; adopt enables at **project scope** (2 repo settings keys, recorded as a `json-merged` entry) + a new user-global **machine entry**; pull re-syncs the cache (A: version-bump→`marketplace update`→`plugin update`; B: reinstall fallback); preflight #8 also hashes the cache copy; eject byte-restores the repo keys always + uninstalls marketplace/cache on the last sibling.

## LOCKED DECISIONS (coordinator)
1. **Plugin version baked into each `core-v*` tag** (maintainer bumps `plugin.json` at tag-cut; the whole-tree lock pins it — pull can't edit a locked tree without failing preflight #6). Joins the stability contract. Mechanism B (reinstall) covers a same-version collision.
2. **Manifest schema v2 = a parallel top-level `machine_entries[]` array** — do NOT add an action to `ACTIONS` or a path into `entries[]` (that would break the adversarially-hardened repo-relative escape guards + preflight #8 jq). `load_manifest` `setdefault`s it to `[]` (v1 migrates free). `cmd_reverse` (Python) stays over `entries[]` only; machine reversal lives in bash `cmd_eject`.
3. **Adopt enables at project scope** — writes exactly `extraKnownMarketplaces.<mkt>` + `enabledPlugins.<plugin>@<mkt>` to `.claude/settings.json`, recorded as ONE `json-merged` entry (existing byte-restore reverses it).
4. **Memory-hook code resolves from the pinned clone, NOT bundled.** The plugin carries only a thin `hooks/memory-hook.sh`; it sources `$CLAUDE_PROJECT_DIR/.kickoff/instance.env` and execs `$KICKOFF_CORE_DIR/memory-retrieval/hook.mjs` (single-sourced + whole-tree-pinned). `${CLAUDE_PLUGIN_ROOT}` locates only the thin shell. Bundling the heavy `memory-retrieval/` would reintroduce copy-drift — forbidden. The cache holds only static wiring (skills/agents/hook-shell/MCP decl).
5. **`plugin/` is canonical for adopters; kickoff-itself KEEPS its `.claude/skills` + `.claude/agents` copies** (meta-repo) and its existing memory hook. Accept possible in-repo drift between `plugin/` and `.claude/`; a sync-check is a later item if it bites — don't over-build (one real adopter).
6. **Marketplace name `kickoff-local`; accept per-machine re-adopt.** The committed `settings.json` `extraKnownMarketplaces` carries a machine-specific clone path — recorded as `json-merged` (byte-restore-reversible), acceptable for the single-adopter reality. **DOCUMENT this machine-specific-path limitation** in the design reconciliation + flag the multi-interactive-adopter-on-one-box collision (same marketplace name, different clone paths) as a revisit-when-it-exists item. Not a framework now.

### ⚠ COORDINATOR CORRECTION to the planner's Slice 1 (dogfood-safety — load-bearing)
The `session-run.sh` `--plugin-dir` wiring MUST be gated **strictly on `KICKOFF_CORE_DIR` being set AND `$KICKOFF_CORE_DIR/plugin` existing** — with **NO `$REPO_DIR/plugin` fallback**. Rationale: this repo IS the live headless worker's engine; the origin has NO `KICKOFF_CORE_DIR` (verified) and NO `enabledPlugins` (verified), so a `KICKOFF_CORE_DIR`-gated arg keeps the origin **100% inert** on its next refresh — it never auto-loads the half-built plugin (which would risk a memory-hook double-fire + MCP conflict). A `$REPO_DIR/plugin` fallback would activate the plugin for the live origin the moment `plugin/` exists — FORBIDDEN. Implement as an array:
```bash
PLUGIN_ARGS=()
if [ -n "${KICKOFF_CORE_DIR:-}" ] && [ -d "$KICKOFF_CORE_DIR/plugin" ]; then
  PLUGIN_ARGS=(--plugin-dir "$KICKOFF_CORE_DIR/plugin")
fi
exec claude --channels "$CHANNEL_SPEC" "${PLUGIN_ARGS[@]}" --permission-mode ... --effort ... --append-system-prompt ...
```
**Required test assertion:** an origin-shaped config (no `KICKOFF_CORE_DIR`) → argv contains NO `--plugin-dir`; an adopter-shaped config (`KICKOFF_CORE_DIR` set + plugin dir exists) → argv contains `--plugin-dir <dir>`.

## INVIOLABLE INVARIANTS (every slice)
- **Adopter-untouched is load-bearing** — pull/plugin-resync never edits the adopter's own files. The acceptance test proves it byte-for-byte (`cmp -s`, mirroring `pull-selftest.sh:334-338`).
- **Credential-safety** — the fresh plugin flow writes/reads NO secret. `settings.local.json` is NOT touched (the hook is delivered by the plugin, not a `hook-installed` entry). `SECRET_BEARING_BASENAMES` backstop (`adopt-manifest.py:76`) stays intact. Machine entries carry only marketplace/plugin/clone-path/scope — never bytes.
- **Every new file write routes through `_open_secure_tmp` + `_real_within` + `_write_seam`** (`adopt-manifest.py:240,714,383`). NO new `open(path,'w')` / predictable-tmp — the symlink-exfil class was closed twice (eject §14, pull Fix B); do not reintroduce it.
- **Fail-closed on missing/ambiguous state; the live headless origin stays INERT** — every new step is gated on the adopter having a plugin machine entry (or `KICKOFF_CORE_DIR`). kickoff-itself has none → the step calls `claude` ZERO times. A dogfood-safety assertion (zero `claude` invocations on an origin-shaped fixture) is REQUIRED in every relevant test.
- **Test isolation** — any real `claude plugin` call uses `CLAUDE_CONFIG_DIR=<scratch>` ONLY, never the live `~/.claude/plugins/` (the running worker depends on it). The selftest prefers a **stub `claude`** on `PATH` for hermetic/fast/deterministic runs.
