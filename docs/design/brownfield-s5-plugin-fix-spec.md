## FIX 1 — [HIGH] eject destroys a SHARED user-global cache for a same-tag / not-yet-pulled sibling
**Files:** `scripts/kickoff` cmd_eject (~962-1001), `scripts/adopt-manifest.py` (adopters-siblings ~1539-1555, adopters-register call sites), cmd_adopt.
**Root:** eject's last-sibling gate (`kickoff:962-964`) flips `_is_last=1` when `adopters-siblings --tag <mytag>` is empty. But `adopters-siblings` (adopt-manifest.py:1555 filter `t and t != args.tag`) reports ONLY DIFFERENT-tag adopters — by design (built for the pull worktree-parking decision). The user-global cache is keyed `<mkt>/<plugin>/<version>` and same-tag ⇒ same version ⇒ SHARED cache dir; eject `rm -rf`s the whole `cache/<mkt>/<plugin>` parent (ALL versions), so even a DIFFERENT-version sibling shares the marketplace + parent dir. So a same-tag (or any-other) sibling is invisible → eject uninstalls + `marketplace remove` + `rm -rf` the shared cache → silently breaks the live sibling (its preflight #8 then fails-closed → its worker won't start). Compounding: `adopters-register` is called ONLY in `cmd_pull` (kickoff:570), NEVER in `cmd_adopt` — so an adopted-but-not-pulled sibling (whose adopt already populated the shared cache) isn't in the registry at all.
**Fix:**
- (a) The shared-cache-removal decision must consider **ALL other registered adopters regardless of tag**. Add an adopt-manifest.py query (e.g. `adopters-others --repo <self>`) that returns every registered adopter repo EXCEPT self, ANY tag. eject removes the user-global marketplace/uninstall/cache ONLY when that returns EMPTY (positively the sole adopter). Do NOT reuse the different-tag-only `adopters-siblings` for this decision.
- (b) Register the adopter at ADOPT time too — after `_adopt_enable_plugin` populates the cache, call `adopters-register` with the pinned core's tag (from the core clone / `_core_tag`), so every cache-populating adopter is visible. (Keep the pull-time registration too.)
- Keep the CONSERVATIVE default (cannot positively prove sole → LEAVE + log). Fix the `--dry-run` message so it doesn't misreport "(last sibling)" when it isn't.
**Regression test (RED on pre-fix):** register a SAME-TAG sibling → `kickoff eject` must LEAVE the marketplace + cache (pre-fix REMOVES them → test fails on old code). Also cover the adopted-but-not-pulled sibling (registered at adopt) → LEAVE.
