# scripts/core-manifest.txt — the CORE file manifest for `kickoff pull`  [R3]
#
# WHAT THESE ARE
#   The CORE files that travel via `kickoff pull`: pulled from a pinned git tag into
#   a read-only clone ($KICKOFF_CORE_DIR) and integrity-pinned in .kickoff/core.lock.
#   They are PULLED-AND-PINNED — NEVER hand-edited in an adopter. preflight check #6
#   fails-closed on ANY drift: a copied-and-patched core file is exactly the fork R1
#   set out to kill, and R3's whole point is that origin's improvement flows in ONCE.
#
# WHAT DOES NOT TRAVEL (instance data — per-adopter, stays local)
#   .kickoff/            — PARTLY tracked: the generated .kickoff/.gitignore keeps the private
#                          bits (instance.env, adopt-manifest.json, core.lock, state/, locks) out
#                          of git; the team-shareable seams (KICKOFF.md, KICKOFF.local.md, bin/,
#                          memory/) are TRACKED on purpose
#   memory-retrieval/memory-index.db     — this adopter's built retrieval index
#   memory-retrieval/eval-set.json       — this adopter's eval corpus (template DOES travel)
#   mission-control/mission-state.json   — this adopter's live board state
#
# FORMAT
#   One repo-root-relative path per line. Blank lines and `#` comment lines are ignored.
#   `kickoff pull` reads THIS file from the pinned checkout (so each tag defines its own
#   core set) and checksums each path relative to $KICKOFF_CORE_DIR into core.lock.

# ── §5 THE PLUGIN — the engine packaged as a Claude Code plugin (design §1.3/§2.2) ──────────────
#   The plugin lives at ~/kickoff-core/plugin/ in the pulled clone. `kickoff adopt` registers it as
#   a PROJECT-SCOPE local-path marketplace (kickoff-local) + enables it (2 repo settings keys);
#   `kickoff pull` re-syncs its user-global cache; the interactive session runs from that cache and
#   the headless worker execs it via `--plugin-dir`. Listed here so the plugin TRAVELS with the tag
#   and the whole-tree lock (format 2) PINS every file at the pinned commit — the plugin `version`
#   is baked into each core-v* tag (LOCKED decision #1), so a pull always re-syncs deterministically.
#   The heavy memory-retrieval/ engine is NOT bundled: the thin plugin/hooks/memory-hook.sh REFERENCES
#   $KICKOFF_CORE_DIR/memory-retrieval/hook.mjs (LOCKED decision #4), which stays single-sourced above.
